# V4 합성데이터 생성 코드

이 모듈은 B용 검수 제안 데이터를 생성한다. 학습·모델 추론을 실행하지 않는다.
기존 V3 패킷과 실험 디렉터리는 수정하지 않으며 출력 경로가 이미 있으면 실패한다.

```bash
python -m kpii_mvp.synthetic_v4 \
  --output-dir /workspace/nfs/datasets/dylee/PII/synthetic_data_bulk3000_v4 \
  --a-model-dir /workspace/korean-pii-mvp/runs/a-native-gpu5-20261019_020722/best \
  --expected-a-manifest-sha256 87fd30cf17ee1afe5ea1d995c9f511bc28d11e5935efdc80750c0a30dd56d591
```

`--a-model-dir`를 주면 A 파일의 해시 잠금만 생성한다. 가중치를 메모리에 적재하거나
학습하지 않는다. 로컬 구조 테스트에서는 이 옵션을 생략할 수 있다.

## 데이터 계약

| 분할 | 문서 | B 후보 | B MASK | B KEEP | 항상 MASK인 이름 |
|---|---:|---:|---:|---:|---:|
| train | 2,000 | 10,500 | 5,775 | 4,725 | 400 |
| valid | 500 | 2,520 | 1,260 | 1,260 | 100 |
| test | 500 | 2,520 | 1,260 | 1,260 | 100 |

V3의 할당 알고리즘으로 유형·라벨·문서 모드별 수량만 결정한 뒤 새 값과 문장으로
렌더링한다. 문서마다 B 후보는 3–8개, 유형은 2–4개다. 문서 모드는 혼합 60%,
전체 MASK 20%, 전체 KEEP 20%이며 각 분할의 10개 가족에 같은 비율로 배분한다.

* ID는 `syn-v4-20261029-...`, source는 `synthetic_rule_based_v4_bulk`다.
* 이름·조직·주소·직위 등 모든 완전한 엔터티 값과 가족은 train/valid/test 간 분리된다.
  따라서 직위도 분할별로 다르며, 미관측 직위에 대한 판단을 함께 측정한다.
* 전화는 `000-0000-0000` 형태, 이메일은 `.example` 도메인이다. 개인 연락처와
  공용 연락처의 전체 값은 겹치지 않는다. 주소는 현실적인 형식을 가진 가공 조합이다.
* 주소의 시·구·도로·건물번호와 선택적인 층·호 전체를 하나의 구간으로 주석한다.
  조직이나 주소 앞에 `가상`을 붙이지 않는다. 실제 기관·주소와 우연히 닮을 수 있다.
* 직위는 `선임연구원`처럼 전체 어휘를 주석한다. 공개 승인 값은 구간 문자열과 완전히
  같은 문자열로 신뢰 메타데이터에 저장한다.

## 위험한 KEEP 반례

직위·부서에 분할별 새 문장을 사용한다. 개인 경력 문장에도 채용·모집·전형 업무가
등장하고, 공개 모집 문장에도 지원자·경력 표현이 등장한다. 단어 하나로 라벨을 정하는
지름길을 줄이려는 설계다. 같은 승인 직위·부서·직장·학교가 한 문서에서 개인 경력과
공개 안내에 각각 등장하면, 앞의 발생은 MASK, 뒤의 발생은 KEEP이다. 순서는 섞는다.
개인·공용 연락처를 동일 값으로 만드는 반례는 넣지 않는다.

유형마다 승인된 개인 용도 MASK는 train 300개, valid/test 각각 72개다. 공개처럼
보이지만 승인되지 않은 값도 MASK로 남는다. `MASK`, `KEEP`, 정답 설명 문구는 본문에
쓰지 않으며, 사유 코드는 주석에만 기록한다.

PHONE/EMAIL/ADDRESS/WORKPLACE/SCHOOL의 분할별 문장 은행은 V3를 재사용하고,
POSITION/DEPARTMENT 문장 은행을 교체했다. 분할 간 동일한 값 제거 문장도 감사한다.
이는 의미가 비슷한 문장을 완전히 제거했다는 뜻은 아니다.

## 검수와 한계

`review/`에 3,000문서 검수 양식, `review_sample_50/`에 train 20·valid 15·test 15
문서 검수 양식을 쓴다. 패킷 루트의 HTML/Markdown 프리뷰는 이 50문서를 보여 준다.
`generation_manifest.json`은 원문·분할·계획·감사·검수 파일 해시를 묶는다.

`audit_v4`는 구간·라벨/관계·승인 일치, 기존 수량 계약, 개인/공용 연락처 분리,
값·가족·문장 분할 누수, 실제 연락처 형식 혼입, 본문 정답 노출을 검사한다.
감사 통과는 자연스러움과 실제 개인정보 보호 성능의 인증이 아니다.

모든 검수는 `PENDING`, `human_reviewed=false`다. test는 V3 오류 분석 후 새로 만든
**미검수 합성 holdout**이며, 외부 실제 문서에 대한 독립 확증 평가로 해석할 수 없다.
이 데이터를 학습에 쓰려면 기존의 명시적 미검수 합성 실험 경로를 사용해야 한다.
